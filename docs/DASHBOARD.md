# Desktop dashboard

ExorSystem is a local evidence and cleanup workspace. The sidebar groups the tools by task; **Overview** shows installed inventory, session counts, recent observations, and cleanup outcomes. The dashboard does not need the driver or an elevated process.

## Arrange the workspace

- Open a tool from the sidebar. Workspace panels can live in **Main**, **Right dock**, or **Bottom dock**. Drag its tab to another dock, or open the **Dock [panel name]** button beside its tabs and choose a destination. Empty right and bottom drop targets appear while dragging. Drag onto a tab to insert before it.
- Drag the separator to size a split. For keyboard use, focus the separator and press its arrow keys; **Home** and **End** set its smallest and largest sizes. Narrow or short windows show a dock switcher instead of piling up small splits. Growing the window restores the saved split sizes.
- In the sidebar, use arrow keys or **Home/End** to switch tools. In a dock's tab strip, use **Left/Right** or **Home/End** to switch tabs, **Ctrl+Left/Right** to reorder, and **Delete** to close the selected tab. You can also use that dock's **Close [panel name]** button. Open a closed tool from the sidebar to return it to its last dock.
- Use **Layout** in the workspace header for **Investigation layout** (inspector and Watch), **Cleanup layout** (batches and dry run), or **Reset layout**. Presets do not start work or change your records. Tab placement, selection, and sizes are saved locally. Form drafts, active operations, and scroll positions live only in the current app session; closing or moving a tab does not cancel a Watch or Scan. Use the operation's own cancel control.
- Open **Activity log** from the sidebar, the status bar’s **Log** button, or **Ctrl+`**. On Windows it is a separate window attached below ExorSystem, not a dock tab. It follows the main window and minimizes with it. **Close** or **Alt+F4** in the log hides it without deleting messages. Closing it while ExorSystem is maximized gives the main window the full monitor work area again. **Clear** resets session messages (including the latest message in the status bar), not recorded evidence. **Script preview** stays separate and read-only.

## Tools

| View | What it shows | Where the data comes from |
|---|---|---|
| **Applications** | Search by name, publisher, or version. Filter classic, MSIX, portable, and recorded entries. Sort by name or reported size; missing sizes come last in size order. Select an app to see its registration, filter and page through a linked session’s recorded items, and trace an item or inspect the session. Scroll the detail card independently in a wide dock; in a narrow dock, **Back to applications** returns to the selected row and page. | Windows uninstall registrations, current-user packages, opted-in portable entries, and local session records. | **Registry monitor** | Choose snapshot scopes, check the baseline, and see which sources were compared or skipped. Save and reapply scope presets. Reopen recent saved comparisons or browse recent registry observations. | Explicit file folders and Software subtrees; services and scheduled-task metadata are separately opt-in. | **Change inspector** | Side-by-side registry and file lists with installation, literal path, change-type, and UTC date filters. Registry snapshots show key presence or a last-write change, not the raw timestamp or the values. A missing fingerprint is not proof of absence. |
| **Relationships** | Trace a recorded path and follow links to its origins, dependencies, and dependents or shared nodes. Select a node to trace it in turn. | A bounded, one-hop view of recorded relationships with evidence sources and confidence, not an exhaustive Windows dependency analysis. |
| **Activity log** | Recent messages with time and severity; scroll up to review older messages. | The desktop's in-memory log for this run, not the durable SQLite ledger. |
| **Script preview** | Inspect the executable path and arguments of a supported, currently registered vendor uninstaller. | The same live command resolution the wizard uses. This is a read-only terminal-style panel, not a shell or script runner. |

Green identifies candidates for reversible quarantine, red identifies protected items to keep, and amber identifies review-only items. | Engine decisions for the chosen policy. ## Watch an install

1. In **Registry monitor**, enter an application or test name. Add full folder paths, specific registry subtrees, or both. No folders are selected for you. Leave the optional installer path blank for a test; ExorSystem never launches an installer from Watch.
2. Leave **Services** and **Scheduled tasks** unchecked for file- or registry-only work. If you opt in, these are read-only checks. Windows can deny access; do not run ExorSystem as Administrator to retry.
3. Choose **Take baseline**. The coverage cards identify captured baselines and excluded scopes. If some were skipped, expand **Skipped scope details**; continue with the usable baselines, or cancel and choose narrower scopes. Then make your test changes or run your installer yourself.
4. Choose **Compare snapshots**. If you enabled **Strict file comparison** before the baseline, Watch rehashes files even when size and modification time match. This reads more file data. **Not requested** and **Skipped** have no change count. A scope that was actually compared can report zero. **Partial** means only some of the selected folders or subtrees were comparable. **View recorded changes** opens that session in Change inspector. Use **Set up another watch** to reuse or edit your input.

A missing folder or registry subtree can appear or disappear between snapshots. A folder with reported read or hash failures, an unreadable task definition, or an incomplete registry subtree is excluded rather than diffed against an incomplete listing. For new comparisons, **Change inspector → Installation → Watch coverage** shows the same scope counts and skip details after restart, even when filters leave the change list empty. A result with no usable pairs also links to its saved coverage. Older sessions, cancelled watches, and failed writes have no saved comparison; a blank list does not establish coverage. The profile stores counts and skipped-scope details (which can include paths), not the snapshots or registry values. **Save report** in Applications includes the counts, not the skip diagnostics. **Compared** means a usable snapshot pair for the selected source, not proof that nothing else changed on Windows.

**Saved scope presets** stores only folder paths, registry subtree paths, and the optional system checks in local desktop preferences. It does not store the application name, installer path, or snapshots. **Apply scopes** replaces the scope fields without starting a capture; review them before taking a baseline. Use **Forget preset** to remove a saved choice.

Use **Stop capture** while either snapshot is running. It is cooperative: the current read may need to finish. A cancelled comparison does not save observations or coverage; if the comparison already committed, the saved result is shown instead. **Cancel watch** abandons the baseline between captures. Closing the main window stops cancellable work and waits for other active work to finish, without terminating a vendor uninstaller. On restart, an interrupted session is marked not completed, with no invented end time, coverage, or changes. Its in-memory baseline cannot be resumed. **Recent comparisons** lists the six newest saved Watch sessions, including zero-change and coverage-only results but not cancelled or interrupted runs without a saved comparison.

## Export matching changes

In **Change inspector**, set the installation, path, change-type and optional UTC dates (From inclusive, Before exclusive), then expand **Export matching changes** and choose **Save changes JSON**. The export applies those filters across all domains, regardless of inspector layout or page. It writes a new `ExorSystem changes.json` in your Windows Documents folder (adding a numbered suffix rather than overwriting). The versioned file records the applied filters and up to 1,000 matching observations in the part, with an exclusive cursor if older matches remain. **Save next older JSON part** continues with the same filters. It contains recorded paths and fingerprints: review it before sharing. Use the saved coverage panel or the installation report for scope coverage; a JSON file with no matches is not proof of coverage.

## Prepare a cleanup and review a batch

In **Cleanup summary**, choose a completed session and the exact classic Windows registration, and explicitly link them if needed. Find application folders, select the eligible ones, and use **Review cleanup plan…**. This reads current file identities and fingerprints but moves nothing. The plan separates included paths from exclusions, including read-only system evidence. Open each included-file page, check the exact-count approval, and confirm. The same approval applies to **Review exact files…** in the uninstall wizard: it reviews leftovers, not files attributed to an installation session. Choosing a policy in Settings changes the default for a new plan or simulation unless you select a local override. A plan expires after ten minutes and cannot be reused; rebuild one if file contents, identities, registration or eligible scope changed.

Quarantine uses same-volume moves; other volumes are not copied. A restore or purge interrupted before completion is shown for review. Review and retry the original operation; an interrupted purge is never automatically resumed.

Choose **View batch** in Cleanup summary to page through the stored manifest’s original file paths, logical sizes, and creation time—even after restore or purge. Previewing does not read held files or check the current destinations. For a held batch, choose **Review restore…** (or **Restore…** in the batch table), then **Confirm: restore files** to request the whole batch. ExorSystem revalidates the batch and original paths and does not overwrite existing files or apply registry entries. Use **Cancel restore** or **Escape** in the review to leave it untouched. Permanent deletion has its own separate confirmation.

## Uninstall wizard

1. **Review plan.** Select a supported machine-wide classic app in Applications and open **Uninstall wizard**. Check the resolved executable and its separate arguments. Use Windows Settings for per-user or unsupported programs; MSIX and portable entries have no local uninstall action.
2. **Vendor uninstall.** Confirm before launching. The desktop refuses a changed registration and does not fall back to a shell or elevation. While it waits, the progress indicator is indeterminate; a return code is not proof the app disappeared.
3. **Review leftovers.** Run the read-only check separately. Review warnings, select eligible folders, and prepare the exact file plan before confirming any move. A matching folder is not proof of ownership. Registry keys, services, and scheduled tasks are never moved or changed. You can open this review without running a vendor uninstaller.
4. **Summary.** See what ran and whether a quarantine batch was created. Moving files does not permanently delete them. Confirm any permanent deletion separately in Cleanup summary.

Press Escape to close the wizard when it is not busy. Workspace shortcuts do not switch panels while the modal wizard is open.

## Back up or rotate a local profile

Under **Settings → Profile storage and backup**, measure file lengths, choose a destination, and make a verified backup. This leaves the active profile unchanged. **Restore to separate copy** rechecks the backup and publishes a new directory; it never replaces or mounts a live database. To free local held-file space while retaining the archived bytes, choose **Rotate verified archive…** on a held batch and supply the backup folder. If the archive or the local batch doesn't verify, the operation does not authorize deletion. Both rotate and restore preserve History. Keep copies somewhere durable; the index checks bytes, not the trustworthiness of whoever supplied the backup.

## Browser preview

Run `npm ci` and `npm run dev` from `gui/` and open the Vite page in a regular browser. The **Demo data** badge identifies an in-memory fixture, with Activity log as a browser panel instead of a native window; actions there never launch Windows processes or inspect or change the host. The fixture is not included in production bundles or used by Tauri. Browser tests use a separate mocked IPC fixture to check the built interface. Use the [Windows release runbook](WINDOWS-RELEASE.md) for optional native tests on exact packages.
